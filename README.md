# سَنَد | SANAD

منصة ويب مدعومة بالذكاء الاصطناعي لخدمة المحتوى الإسلامي الموثوق، مبنية وفق المرجعية والحزمة العلمية المعتمدة (تحدي الذكاء الاصطناعي في خدمة المحتوى الإسلامي - باذل / سدايا SDAIA / Future Frontiers) والهوية البصرية الرسمية لـ SAND.

---

## 🌟 مميزات المشروع (Features)

1. **دعم 3 لغات رئيسية:**
   - الإنجليزية (English)
   - الأردية (اردو) مع دعم كامل لتخطيط اليمين لليسار (RTL)
   - البنغالية (বাংলা)
2. **تجربة صوتية متكاملة (Voice-to-Voice):**
   - تسجيل السؤال صوتياً (Speech-to-Text).
   - استماع للإجابة صوتياً (Text-to-Speech) بنفس لغة السائل.
3. **ضبط مستويات المحتوى الأربعة (A, B, C, D):**
   - **Level A:** حقائق ومعلومات أصلية مستقرة (القرآن، الصحيحان، أركان الإسلام).
   - **Level B:** شروح وتعريفات واستدلالات دعوية.
   - **Level C:** مسائل خلافية فقهية مع بيان الخلاف دون ترجيح تعسفي.
   - **Level D:** فتاوى وقضايا شخصية (الامتناع عن الإفتاء الآلي المستقل والإحالة لشخص مختص).
4. **مقاومة الهلوسة وفحص الأحاديث:**
   - رفض اختلاق الأحاديث أو الروايات التي لا أصل لها في الكتب المعتمدة.
5. **نظام إحالة المختصين (Specialist Handoff):**
   - تجهيز تذكرة فقهية منظمة للباحث متحدث لغة السائل متضمنة السؤال، وسياقه، والمصادر التي تم فحصها.
6. **10 اختبارات قياسية مدمجة (Benchmarks Runner):**
   - مطابقة لحالات الاختبار الواردة في الصفحة 6 من مستند المرجعيات.

## 🚀 كيفية تشغيل المشروع على جهازك (Local Setup)

### المتطلبات الأساسية:
- تثبيت **Node.js** (إصدار 18 أو أحدث). رابط التحميل: [https://nodejs.org](https://nodejs.org)

### خطوات التشغيل:

1. **فك ضغط الملف (Unzip):**
   قم بفك ضغط ملف `sanad-project.zip` في أي مجلد على جهازك.

2. **فتح موجه الأوامر (Terminal / Command Prompt):**
   افتح الـ Terminal وانتقل إلى مجلد المشروع:
   ```bash
   cd sanad-project
   ```

3. **تثبيت الحزم (Install Dependencies):**
   ```bash
   npm install
   ```

4. **تشغيل الخادم المحلي (Run Dev Server):**
   ```bash
   npm run dev
   ```

5. **فتح الموقع في المتصفح:**
   افتح المتصفح على العنوان التالي:
   ```
   http://localhost:3000
   ```

## 🗄️ قاعدة البيانات (Supabase)

كل الإعدادات تُقرأ من متغيرات البيئة فقط. لا توضع أي مفاتيح في الكود.

1. انسخ `.env.example` إلى `.env` وضع القيم من لوحة Supabase:
   `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_PROJECT_REF`, `SUPABASE_DB_PASSWORD`
2. اربط المشروع وطبّق الـmigrations:
   ```bash
   npm run db:link        # مرة واحدة
   npm run db:push:dry    # عرض ما سيُطبَّق دون تنفيذ
   npm run db:push        # تطبيق supabase/migrations على مشروعك
   npm run db:check       # التحقق من الاتصال ووجود الجداول الـ28
   ```
3. بعد أي migration جديدة: `npm run db:types` لتحديث `server/db/database.types.ts`.

| المجلد | المحتوى |
|---|---|
| `supabase/migrations/` | المخطط الكامل: الجداول، العلاقات، الفهارس، سياسات RLS |
| `server/db/` | طبقة الوصول (للخادم فقط): العملاء، الـrepositories، الأنواع |
| `scripts/db/` | سكربتات الربط والفحص والتطبيق المحلي |
| `tests/` | اختبارات الوحدات، والمخطط، والـRLS، والـrepositories عبر PostgREST |

**الاختبارات:** `npm test` يشغّل اختبارات الوحدات دائمًا. اختبارات قاعدة البيانات تعمل عند ضبط
`TEST_DATABASE_URL` (PostgreSQL محلي مع pgvector)، واختبارات الـrepositories تحتاج أيضًا `POSTGREST_BIN`.
كل اختبار ينشئ قاعدة مؤقتة خاصة به ثم يحذفها، ولا يلمس مشروع Supabase.

## 🧠 طبقة الإجابة (RAG — OpenAI)

كل الأسئلة تمر عبر `POST /api/ask` على الخادم فقط:

سؤال ← تنظيف ← تحديد اللغة ← تصنيف المستوى (أ–د) ← استرجاع من المحتوى **المنشور فقط** ← تصفية المصادر ← تقييم الثقة ← توليد مقيّد بالمصادر ← فحص الاستشهادات والاقتباسات ← إجابة موثقة، أو اعتذار آمن/إحالة لمختص.

- لا توجد إجابة بدون مصادر مسترجعة. النصوص الشرعية والاستشهادات تُبنى من قاعدة البيانات، لا من النموذج.
- مفتاح OpenAI والعتبات في متغيرات بيئة الخادم فقط (`OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_EMBEDDING_MODEL`, `RAG_MIN_CONFIDENCE`…) — انظر `.env.example`.
- `npm run rag:embed` يحسب الـembeddings للمقاطع بعد إدخال المحتوى.
- عند عدم ضبط OpenAI/Supabase تعمل الواجهة بالمحرك التجريبي القديم وتعرض تنبيه "وضع تجريبي".
